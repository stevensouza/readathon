What Happens During Upload (click to expand)
  1. Names are checked against the roster first: saved name corrections and names that differ only in capitals/spaces are matched automatically; other names are listed in Match names to the roster
  2. ALL existing cumulative data is replaced (not incremental)
  3. Names not matched are imported with "ERROR: NO ROSTER MATCH" tag
  4. read-a-thon.com also lists an empty placeholder row (PageCreated = No) for students; it adds nothing, so it's only reported when two rows for a student both have data
  5. Successfully processed entries are saved to the database
  6. A copy is saved as the snapshot for the chosen snapshot date (replacing any earlier copy for that date)
  7. Upload history is updated with status and student counts

A name correction links a name a parent typed on read-a-thon.com to a roster student. It's saved when you accept a match in Match names to the roster, and every upload uses it (same name and teacher, ignoring capitals and spaces). Each class is separate: "Ellie" in two classes is two corrections.

Change or delete one at any time - it applies to uploads from then on. Days already uploaded keep the earlier choice until you upload them again (the daily files for those days and the latest cumulative file).

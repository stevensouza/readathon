Read-a-Thon System - User Manual

Daily Steps (during the contest)

  1. Upload the day's minutes: 📤 Upload → Daily Minutes Upload → choose the day's CSV file(s) from ReadAThon.com.
  2. Upload the cumulative file: 📤 Upload → Cumulative Stats Upload. Check the snapshot date - it should be the contest day the file covers (it defaults to the latest day with minutes).
  3. Open the Daily Scoreboard: 📰 Bulletins → Daily Scoreboard (it opens on the latest day).
  4. Copy as image and paste it into the email (or Download PNG and attach it).

Before the contest starts: 📰 Bulletins → Meet the Teams introduces the teams. After the last day: 📰 Bulletins → Prize Scoreboard shows the Final Prize Winners.

Simple View

The ✨ Simple view button (top right, next to the database selector) hides everything except the daily job: Upload, Bulletins, Help and the database selector. The app opens on the Daily Scoreboard, and the Upload page hides its delete buttons.

  • ☰ Full view brings back every page: School, Teams, Grade Level, Students, Reports & Data, Workflows, Admin.
  • The choice is remembered, even after restarting the app.
  • It can also be set when starting the app: ./run.sh --simple or ./run.sh --full.
  • Simple view only declutters the screen - hidden pages still work if you type their address.

About ReadAThon.com Data

This application requires CSV data from ReadAThon.com

The Read-a-Thon System is designed to enhance and extend the data you download from the official ReadAThon.com platform. While ReadAThon.com manages pledges and online donations, this application adds:

Additional Features
  • Team competition tracking and leaderboards
  • Daily reading minute caps (120 min/day max)
  • Participation rate calculations
  • Grade-level and class-level analytics
  • Custom reports and data exports
  • Multi-year database management
How to Get Data
  1. Log in to ReadAThon.com
  2. Navigate to your school's dashboard
  3. Download CSV exports (daily logs and cumulative stats)
  4. Use the Upload tab to import into this app
Next Steps: After installation, visit ReadAThon.com to download your school's data, then use the Upload page to import it into the system.
Get the Application: Download or clone from GitHub: github.com/stevensouza/readathon
See the Installation Guide for complete setup instructions.

Data Persistence

Your Data is Safe!

All data is permanently stored on your Mac's hard drive in SQLite database files:

  • db/readathon_2026.db (one per event year) - Your real read-a-thon data
  • db/readathon_sample.db - Sample test data

The data is NOT stored in memory - it survives:

  • ✅ Stopping and restarting the application
  • ✅ Computer restarts
  • ✅ Power outages
  • ✅ Everything!
You can safely close the app at any time. Your data will still be there when you restart!

Production vs Sample Data

What's the Environment Selector?

The dropdown in the top-right corner lets you switch between two completely separate databases:

Production
  • Your real read-a-thon data
  • 411 students pre-loaded
  • All real daily uploads go here
  • Use for actual reporting
Sample
  • Test data for practice
  • Same student roster
  • Safe to experiment
  • Use for learning/testing
Note: The two environments are completely separate. Data uploaded to Sample will NOT appear in Production!
✏️ Editable vs 🔒 Read-only Databases

You can view any database, but only one database can be changed: the editable database (normally this year's). Uploads, upload deletes and Clear Tables are blocked on every other database, so looking at last year's numbers can never send today's files to the wrong year.

  • Editable: the database selector shows ✏️ and has a green left edge.
  • Read-only: grey header bar (amber for Sample), the selector shows 🔒 with a dashed border and a small 🔒 READ-ONLY label under it, and the Upload page is greyed out with a Switch to ... button that takes you to the editable database.
  • The selector marks each database with ✏️ or 🔒. Switching databases never changes which one is editable.
  • To change it, go to Admin → Database Registry and click Make Editable (you'll be asked to confirm). A new year's database created in Admin → Database Creation becomes editable automatically unless you untick the box.
  • Until you choose, the newest year database (readathon_YYYY.db) is editable; Sample is read-only like any other database.

Interface: All Application Tabs

The application provides 10 main tabs for navigating different aspects of the read-a-thon. Each tab serves a specific purpose, from viewing school-wide metrics to managing databases.

School Tab

Purpose: School-wide overview with at-a-glance metrics, team competition, and top performers.

Related: Teams Tab for detailed team comparisons, Students Tab for individual student data

Headline Banner (6 Metrics)

The dark blue banner at the top displays 6 key metrics in a horizontal row:

  • 📅 Campaign Day: Current day of total days + date (does NOT honor date filter)
  • 💰 Fundraising: Total $ + student count + % (does NOT honor date filter)
  • 📚 Minutes Read: Hours + minutes (120/day cap, honors date filter, shows ◐ icon when filtered)
  • 🎁 Sponsors: Count + student count + % (does NOT honor date filter)
  • 👥 Avg. Participation (With Color): % + student count (honors date filter, can exceed 100%, shows ◐ icon)
  • 🎯 Goal Met (≥1 Day): % + student count (honors date filter, shows ◐ icon)
Date Filtering

Filter Period dropdown above banner allows filtering by:

  • "All Days": Cumulative data across entire read-a-thon
  • Single Date: Cumulative data through specific date
  • Relative Days: "Day 1", "Day 2", etc.

When date filter is active, the ◐ icon appears on metrics that honor the filter (Minutes, Avg. Participation, Goal Met). Hover over ◐ to see tooltip: "Cumulative through [date]".

Additional Sections
  • Team Competition: Head-to-head comparison cards for both teams
  • Top Performers: Leading students and classes
  • Participation Breakdown: Daily engagement trends

Purpose: Detailed head-to-head team competition metrics and leaderboards.

  • 4-column layout: 2 rows × 4 cards per team (8 cards total)

Students Tab

Purpose: Individual student performance with master-detail view.

Related: Grade Level Tab for class and grade comparisons, School Tab for overall top performers

Upload Tab

Purpose: Import daily reading data and cumulative stats from ReadAThon.com.

Related: Reports & Data Tab uses uploaded data, Admin Tab for viewing upload history and clearing data

Two Upload Types

1. Daily Minutes Upload

  • When: Every day after students read
  • File: CSV with Reader Name + Minutes
  • Updates: Daily_Logs table

2. Cumulative Stats Upload

  • When: Once per contest day (after that day's minutes)
  • File: CSV with Reader Name + Donations + Sponsors
  • Snapshot date: the contest day the file covers. Defaults to the latest day with daily minutes (the Day 5 file is often uploaded the morning of Day 6); change it if needed
  • Updates: Reader_Cumulative (latest) and a saved copy for that day in Reader_Cumulative_History. Uploading again for the same day replaces that day's copy

Process: Select date (for daily upload) → Choose CSV file → Click Upload button → System validates names against roster and shows warnings for unrecognized students.

📰 Bulletins

Purpose: Branded one-page bulletins (school masthead, team colors) built from the data and meant to be emailed as an image: the teams before the contest, the daily update, and the prize results.

Related: Upload Tab (upload the cumulative file each day so money raised can be shown for that day), Admin Tab (school name and contest days)

Meet the Teams

  • Built from the roster only, so it is ready as soon as the year's database is created - send it before the contest starts
  • Total students, the two teams side by side (students, classes, grades), and each team's classes with how many students each teacher brings
  • Kindergarten AM and PM classes are listed separately; the download is extra sharp so it can be printed or zoomed

Daily Scoreboard

  • % of students who read at least 1 day, Day N of the contest
  • Students: daily prize drawing winner per grade (from students who met their grade goal that day)
  • Classes: highest participation % in each grade, school-wide leader tagged "Top"
  • Teams: participation, minutes and money raised, with today's figures and trophies for the leader
  • Showdown: this year vs last year on the same contest day (when last year's database is registered)

Prize Scoreboard

  • "Prize Leaders — as of Day N" during the contest; "Final Prize Winners" once the last contest day is reached
  • Team Participation, Top Student Earner, Highest Class Participation, Grade Level Participation, Top Minutes / Donations / Sponsors per grade, Goal Getters
  • Every tied winner is listed ("N-way tie")
  • Kindergarten AM and PM classes compete as separate classes
Using them
  • As of (scoreboards): pick any contest day (defaults to the latest). Minutes and participation count through that day.
  • Redraw prize winners (Daily): the drawing is repeatable - reloading shows the same winners. Redraw picks new ones and the header shows "Drawing #N" so everyone knows which draw it is.
  • Copy as image / Download PNG: captures only the bulletin (not the buttons) - paste it into an email.
  • Not available*: money raised is only known for days with a saved cumulative upload (see Upload → snapshot date). Earlier years kept only their final totals.
  • Settings: Admin → Actions → Bulletin Settings: school name (masthead) and contest days (default 10, for "Day 7 of 10").

Runs 10 final prize winner reports:

Runs all 23 main reports in sequence

Participation
A student "participated" if they read more than 0 minutes that day
Meeting Goal
A student "met their goal" if they read at least their grade's minimum daily minutes
Credited Minutes
Maximum 120 minutes per day counts toward totals (actual minutes are still tracked separately)
Tie-Breaking

Troubleshooting

See also: Upload Tab for data import help, Admin Tab for database management tools

Common Issues

Solution:
  • Check that student names match exactly (case-sensitive)
  • Verify CSV column names are correct
  • Look for extra spaces in student names

Solution:
  • Make sure you've uploaded data first
  • Check which environment you're in (Production vs Sample)
  • Verify the date filter matches uploaded data

Solution:
  1. To clear selected tables: Admin page → choose tables → Clear
  2. To wipe all uploaded data for a year but keep its roster: python3 clear_all_data.py readathon_2026.db
  3. To restore the sample data: git checkout db/readathon_sample.db
  4. Back up the db/ folder first - real databases are not stored in git

Solution:
  1. Open app.py in a text editor
  2. Find line 197: app.run(debug=True, host='127.0.0.1', port=5000)
  3. Change port=5000 to port=5001 (or another port)
  4. Save and restart the application
  5. Access at http://localhost:5001

Tips & Tricks

  • Test in Sample: Try new features in Sample environment before using in Production
  • Copy to Clipboard: Fastest way to get data into your slideshow - just paste!
  • Export to CSV: Use this for Excel analysis or archiving
  • Run Reports Multiple Times: Reports don't change your data - run them as often as you like
  • Prize Drawing Randomness: Q4 picks different winners each time - run it until you're ready to announce
  • Workflows Save Time: Use QD workflow every day instead of running 5 separate reports
  • Database Comparison for Trends: Use Admin → Database Comparison to track year-over-year growth across all 50 metrics
  • Prepare for Next Year: Use Admin → Database Creation to set up next year's database in advance
  • Multi-Year Planning: Keep all your historical databases in the Database Registry for easy access to past years' data
